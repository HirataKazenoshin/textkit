ケース変換ツールの使い方

このツールを使えば、プログラミングで使われる主要な命名規則（ケース）をワンクリックで相互変換できます。以下の手順で簡単にご利用いただけます。

  1. 変換先のケースを選択：ツール上部のタブから、変換したいケース（snake_case、camelCase、PascalCase、kebab-case、SCREAMING_SNAKE_CASE）を選びます。
  2. テキストを入力：左側の入力欄に変換元のテキストを入力します。例えば getUserName や user_first_name などの識別子を入力してください。
  3. リアルタイムで結果を確認：入力と同時に右側の出力欄に変換結果が表示されます。サーバーへの送信は一切行わないため、機密性の高いコードでも安心です。
  4. 結果をコピー：出力欄の右上にあるコピーボタンをクリックすると、結果をクリップボードにコピーできます。

複数行にも対応しています。1行に1つの識別子を入力すると、各行が独立して変換されます。大量の変数名やカラム名を一括変換したい場合に便利です。

命名規則（ネーミングコンベンション）とは

命名規則（ネーミングコンベンション）とは、プログラミングにおいて変数名・関数名・クラス名・定数名などの識別子を命名する際のルールです。チーム開発では、統一された命名規則に従うことでコードの可読性が大幅に向上し、他の開発者がコードを素早く理解できるようになります。

多くのプログラミング言語やフレームワークには推奨される命名規則があり、リンター（ESLint、Pylint、RuboCopなど）によって自動的にチェックすることも可能です。命名規則を守ることは、バグの予防やコードレビューの効率化にもつながります。

以下では、代表的な5つのケース（命名規則）について詳しく解説します。

snake_case（スネークケース）

snake_caseは、単語をアンダースコア（_）で区切り、すべて小文字で記述するスタイルです。アンダースコアが蛇のように見えることから「スネークケース」と呼ばれています。

使用される場面：Python（PEP 8で推奨）、Ruby、Rust、PHP（変数名・関数名）、SQLのテーブル名やカラム名、C言語の関数名などで標準的に使われます。

例：user_name、get_total_count、max_retry_limit、created_at

camelCase（キャメルケース / ローワーキャメルケース）

camelCaseは、最初の単語を小文字で始め、2番目以降の単語の先頭を大文字にするスタイルです。大文字がラクダのこぶのように見えることから「キャメルケース」と呼ばれます。正確には「ローワーキャメルケース（lowerCamelCase）」とも呼ばれ、PascalCaseと区別されます。

使用される場面：JavaScript / TypeScriptの変数名・関数名（最も一般的）、Javaの変数名・メソッド名、C#のローカル変数・パラメータ名、Go言語のエクスポートされない識別子などで使われます。

例：userName、getTotalCount、maxRetryLimit、isActive

PascalCase（パスカルケース / アッパーキャメルケース）

PascalCaseは、すべての単語の先頭を大文字にするスタイルです。「アッパーキャメルケース（UpperCamelCase）」とも呼ばれます。プログラミング言語Pascalに由来する名前です。

使用される場面：ほぼすべての言語でクラス名に使われます。具体的には、Java・C#・TypeScriptのクラス名・インターフェース名、Reactコンポーネント名（必須）、Go言語のエクスポートされる識別子、.NETのメソッド名・プロパティ名などが挙げられます。

例：UserProfile、GetTotalCount、HttpClientFactory、MyAppComponent

kebab-case（ケバブケース）

kebab-caseは、単語をハイフン（-）で区切り、すべて小文字で記述するスタイルです。単語がケバブの串に刺さっているように見えることから名付けられました。

使用される場面：CSSのクラス名・プロパティ名（BEM記法でも使用）、HTMLのカスタム属性（data-*）、URLのスラッグ、npmパッケージ名、CLIコマンドのオプション名などで広く使われます。多くのプログラミング言語ではハイフンが減算演算子と解釈されるため、変数名には使用できません。

例：user-name、get-total-count、my-app-component、background-color

SCREAMING_SNAKE_CASE（スクリーミングスネークケース）

SCREAMING_SNAKE_CASEは、snake_caseと同様にアンダースコアで単語を区切りますが、すべて大文字で記述します。「叫んでいる（screaming）」ように見えることからこの名前がつきました。コンスタントケース（CONSTANT_CASE）とも呼ばれます。

使用される場面：ほぼすべてのプログラミング言語で定数名に使われます。Javaのstatic final変数、Pythonのモジュールレベル定数、JavaScriptのconst定数（特にグローバルな設定値）、C/C++の#defineマクロ、環境変数名などが代表的な用途です。

例：MAX_RETRY_COUNT、API_BASE_URL、DEFAULT_TIMEOUT、DATABASE_HOST

よくある質問（FAQ）

snake_caseとは何ですか？

snake_case（スネークケース）は、単語をアンダースコア（_）で区切り、すべて小文字で記述する命名規則です。PythonやRuby、データベースのカラム名などで広く使われています。例えば、user_first_nameやget_total_countのように記述します。可読性が高く、特にアンダースコアが空白の代わりとして機能するため、長い識別子でも読みやすいのが特徴です。

camelCaseとsnake_caseの違いは何ですか？

camelCase（キャメルケース）は単語の区切りを大文字で表現し、スペースや記号を使いません（例: myVariableName）。一方、snake_caseはアンダースコアで単語を区切り、すべて小文字にします（例: my_variable_name）。JavaScriptやJavaではcamelCaseが主流で、PythonやRubyではsnake_caseが標準です。プロジェクトの言語やフレームワークに合わせて使い分けるのが一般的です。

どのプログラミング言語でどのケース（命名規則）を使いますか？

主な使い分けは以下の通りです。snake_case: Python、Ruby、Rust、PHP、SQL。camelCase: JavaScript、TypeScript、Java、C#の変数・関数名。PascalCase: クラス名（Java、C#、TypeScript）、Reactコンポーネント。kebab-case: CSSクラス名、HTMLの属性、URLスラッグ。SCREAMING_SNAKE_CASE: 定数（多くの言語共通）。ただし、これらはあくまで慣例であり、チームやプロジェクトの規約が優先されます。

PascalCaseとcamelCaseの違いは何ですか？

PascalCase（パスカルケース）は最初の単語も含めてすべての単語の先頭を大文字にします（例: MyClassName）。camelCase（キャメルケース）は最初の単語だけ小文字で始まり、2番目以降の単語を大文字にします（例: myVariableName）。PascalCaseはUpperCamelCaseとも呼ばれ、クラス名やReactコンポーネント名に使われます。camelCaseは変数名やメソッド名に使われるのが一般的です。

命名規則を統一するメリットは何ですか？

命名規則を統一することで、コードの可読性が向上し、チーム開発での認識のズレを防げます。また、ESLintやPylintなどのリンターによる自動チェックが可能になり、コードレビューの効率も上がります。新しいメンバーがプロジェクトに参加した際のオンボーディングもスムーズになり、一貫した命名規則はプロジェクト全体の保守性を大きく向上させます。
