Salesforce API名の命名規則

管理者だけでなく、開発者・導入パートナーにも伝わる名前を最初に決めるための実践ガイドです。

API名は表示ラベルとは別に考える

Salesforceでは利用者が見る表示ラベルを日本語にできる一方、API名は数式、Apex、Flow、連携、データ移行で長く使われます。表示ラベルをそのままローマ字化するのではなく、意味が明確な英単語を使い、変更しない前提で決めることが重要です。カスタム項目には __c、カスタムメタデータ型には __mdt が付くため、接尾辞を名前本体に重ねて書く必要はありません。

まず決める4つのルール

  1. 単語は英語で統一する。「顧客」は Customer、「契約」は Contract のように、組織内の対応表を作ります。
  2. 略語をむやみに増やさない。 Amount は Amt、Number は No. といった短縮を混在させると検索性が落ちます。
  3. 真偽値には状態がわかる語を使う。 Is_Active__c、Has_Consent__c のようにします。
  4. 日付と金額の意味を明示する。 Contract_Start_Date__c、Monthly_Fee__c のように、何の日付・金額かを省略しません。

命名例

表示ラベルAPI名の例補足
契約開始日Contract_Start_Date__c対象と種別を明示
メール配信同意Has_Email_Consent__cチェックボックスであることが読み取れる
請求先会社名Billing_Company_Name__c既存標準項目との混同を避ける

作成前に確認すること

既存項目との重複、連携先での文字数制限、パッケージの名前空間、将来のレポート利用を確認します。特に外部連携がある場合は、画面上のラベルよりもAPI名が契約上の項目名になることがあります。
