Base64 Encoder & Decoder

Encode or decode UTF-8 text in your browser.

What Base64 is for

Base64 represents binary or text data using only 64 printable ASCII characters (A-Z, a-z, 0-9, +, /) plus = for padding. It is commonly used in data URLs, API payloads, email attachments, and authentication-related protocols. Every 3 bytes of input become 4 characters of output, so the encoded text is roughly 33% larger than the original. It is an encoding, not encryption.

How to use this tool

  1. Paste the text you want to encode, or the Base64 string you want to decode, into the Input box.
  2. Select Encode to turn text into Base64, or Decode to turn Base64 back into text.
  3. Check the status message under the buttons, then select Copy result to put the output on your clipboard.

Examples

Encoding Hello, TxConv! produces SGVsbG8sIFR4Q29udiE=. Decoding that string returns the original text.

The tool encodes text as UTF-8 first, so non-English text works too. For example, こんにちは becomes 44GT44KT44Gr44Gh44Gv. Simple scripts that assume plain ASCII often break on this kind of input.

Standard and URL-safe Base64

The Encode button produces standard Base64 with +, /, and = padding. The Decode button accepts both standard Base64 and the URL-safe variant, which uses - and _ instead of + and /; this is the form used in JSON Web Tokens and many URL parameters. If you need URL-safe output, replace + with - and / with _ in the result, and remove the trailing = characters.

UTF-8 support and privacy

Encoding and decoding are performed locally in your browser. The text you enter is not sent to a TxConv server. Do not treat Base64 as a way to protect secrets: anyone can decode it in seconds. To protect sensitive data, use real encryption and transport security such as HTTPS.

Limitations

  • The decoder returns text. If the Base64 contains binary data such as an image or a PDF, the result will look like garbled characters.
  • Very large inputs (hundreds of kilobytes or more) may fail to encode in the browser. For big files, use a command-line tool such as base64.
  • If the input is not valid Base64, the tool shows “The input is not valid Base64.” instead of a result.

Frequently asked questions

Is Base64 encryption?

No. Base64 only changes how data is written. It has no key, so anyone can reverse it. Never rely on it to hide passwords, API keys, or personal data.

Why does my Base64 string end with = or ==?

Base64 works on groups of three bytes. When the input length is not a multiple of three, one or two = characters pad the output to a multiple of four characters.

Why does the encoded text look longer than the original?

Three bytes of input become four characters of output, so the result is about one third larger. That overhead is the price of using only safe printable characters.

Is my text uploaded anywhere?

No. The conversion runs in your browser and the text you type is not sent to TxConv.
